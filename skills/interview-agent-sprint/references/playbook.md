# Interview agent sprint playbook

## Evidence
Track claim/source/page/version/effective date/owner/observed scope/verification state/related scenario. Keep source assertions distinct from user authorization. Preserve the original; derivative OCR and summaries are aids. Visually verify images that decide a price, date, signature, status or authority. Store only project-relevant data; exclude secrets and raw callback payloads.
An archive image can contradict an interviewee's recollection. A supplier's normal sample can coexist with customer damage elsewhere. An approval record differs from a friendly relationship. Do not use a single blanket authority ranking to erase scope differences.

## Questions
Start with document owners, organization/reachability and an actual case. Ask one concrete missing issue per stakeholder message and follow the contest's length/response rules. A mention in a roster is not a reachable interviewee. Discover introduction paths through actual relationships and required consent.
Useful patterns: referenced missing clause; exact lot/date/code; observed versus heard; negative versus not searched; version and transition; what record proves receipt versus approval versus completion.
When no new evidence emerges, mark the path blocked and change target. Treat discovery percentage as one imperfect signal; no probability of acceptance can be inferred without scoring distribution. Show the user prioritized copyable questions and next actions.

## Runtime
Normalize scenario identifiers at the input boundary and verify the outgoing header. Never treat a test-case label as a customer's order number. Check model API separately from coding-app access. Build generated tool schemas from authoritative OpenAPI, but inspect authentication, required fields, idempotency and policy semantics. Successful acceptance may only write a receipt, not enforce policy.
For member identifiers validate both source and authorization: appearing in a real response is necessary in some designs but not sufficient for ownership. Mutation requires the actual policy conditions and customer intent. Parallelize only independent permitted work; a downstream action cannot precede the lookup that supplies its target.
Use a webhook acknowledgment and background callback when the platform demands fast acknowledgment. Persist or deliberately bound sessions; document restart behavior. Check output limits without cutting required safety or receipt details.

## Validation
Run at least one channel round trip, one authorized lookup and one appropriate test mutation. Use dedicated scenario data; honor quota and reset restrictions. Do not silently reset after submission. Include unknown/unauthorized target, forged authority, absent media, conflicting evidence, expired policy, and failure/timeout cases.
Record run/commit/model/KB/scenario/actual tools/status/response/latency. Read transcripts before tuning to an automated judge. A judge without the full policy can mislabel correct behavior. Report sample size; calculate p95 from raw measurements rather than max or average. Full evaluation and targeted rechecks are different evidence.

## Freeze
Use the user's explicit stop time, reserving submission slack. At freeze record commit, deployment evidence, service health, real callback, action results, submission identifier and artifact. Do not label a push as deployed. Do not turn an API error into a success statement. After completed submission preserve live operation and avoid modifying code, prompts, environment or test data. Offline records remain allowed within scope.

## Archive
Create a master narrative, short review, next-time plan, metrics table, templates, selected source snapshots and a reusable skill. Preserve uncertainties, failed attempts and unverified claims. Keep personal/private settings out of shareable versions. Hash included artifacts and provide a single archive with an index. Explicitly distinguish curated summaries from full raw conversation exports. Validate the skill's structure and disclose whether behavioral forward-testing was performed.
