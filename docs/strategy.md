# 문제 해결 전략

[← README](../README.md) · [구조](architecture.md) · [회고](retrospective.md)

## 목표를 네 부분으로 나누기
가상의 산지직송 쇼핑몰 상담 과제를 정보 수집, 근거 판단, 실제 실행, 결과 검증으로 나눴다. 지식을 많이 수집해도 실행을 틀리면 상담 에이전트는 완성되지 않는다. 반대로 연결만 성공해도 정책과 예외를 모르면 오답이 난다.

## 1. 최소 작동 경로를 먼저 만든다
카카오톡에서 질문을 받아 모델을 호출하고 답장을 보내는 경로를 확인했다. 개발 도구를 Claude에서 Codex로 옮겼지만 앱 구독 사용량과 API 잔액을 구분해 동작하던 런타임은 유지했다. 필요 없는 모델 교체보다 실제 문제 해결에 시간을 썼다.

## 2. 인터뷰를 문서 탐색과 연결한다
넓은 질문은 상대가 답할 범위를 정하지 못하게 했다. 한 업무·사건·자료로 좁히면 현장 관찰과 원문 위치를 얻을 수 있었다. 질문마다 ‘무슨 새 사실, 문서, 연결을 얻으려는가’를 정하는 것이 좋았다.
자료는 직함만 보고 소유자를 단정할 수 없었다. 홍보·운영에 물어도 나오지 않던 자료를 생산 측이 가지고 있었다. 문서 참조 관계와 조직 관계도를 따라가야 했다.
이름이 언급된 생산자가 모두 직접 대화할 수 있는 인물은 아니었다. 메일 업무 관계가 카카오톡 소개를 뜻하지도 않았다. 실제 연결 경로와 필요한 동의를 확인해야 했다.

## 3. 모순을 네 축으로 분해한다
| 축 | 확인하는 질문 | 이유 |
|---|---|---|
| 시점 | 두 자료가 같은 순간을 말하는가? | 한 시점의 정상값은 이전 구간 전체를 설명하지 않음 |
| 범위 | 같은 상품·부위·표본을 보았는가? | 출고 표본과 고객의 하자 부위는 다를 수 있음 |
| 판본 | 시행일·경과규정이 같은가? | 과거 안내와 현재 정책이 공존할 수 있음 |
| 권한 | 발언자가 무엇을 승인할 수 있는가? | 친분·약속·승인·이행은 별개 |

인터뷰 상대의 기억을 모든 원문보다 우선하지 않았다. 기록이 있다는 사실과 그 기록의 법적·운영상 효력도 분리했다. ‘없음’은 조회를 거친 결론인지, 아직 확인하지 못한 상태인지 구분했다.

## 4. 업무 API의 성공 의미를 확인한다
도구가 성공 응답을 반환해도 단순 접수일 수 있다. 정책 충족, 접수, 승인, 최종 지급을 하나로 묶지 않았다. 필요한 순서는 대상 특정 → 고객 귀속 확인 → 정책·고객 의사 확인 → API 호출 → 실제 결과에 맞는 안내였다.
모델이 추측한 회원 ID를 사용할 수 있다는 문제는 코드에서 제한했다. 다만 실제 응답에서 얻은 ID라는 사실이 본인 귀속까지 보장하지 않으므로 두 검증은 별개다.

## 5. 실패 시나리오로 조사 우선순위를 바꾼다
공개 예시를 돌려 실제 호출과 누락을 봤다. 약한 흐름에 필요한 근거부터 찾고 지식·프롬프트·코드를 보완했다. 고객에게 불가라고만 말하는 답변에는 실제 허용 대안을 붙였다. 안전 보증 거절 뒤 필요한 이관을 빠뜨리지 않는지도 확인했다.
평가 모델이 전체 정책을 모르거나 고객 시뮬레이터가 일찍 대화를 끝낼 수 있었다. 점수만 최적화하지 않고 원문·대화·도구 결과를 같이 읽었다.

## 6. 병렬화는 병목을 기준으로 한다
이번에는 사용자가 여러 인물에게 질문을 보내고, 답을 옮기면 AI가 분석·구현·검증을 이어 갔다. 화면 자동화는 느려 중단했다. 다중 AI 작업자나 다중 에이전트 런타임을 완성했다고 주장하지 않는다.
다음에는 인터뷰 질문 생성·원문 분석·개발·평가를 공통 파일로 나눌 생각이다. 독립 작업은 병행하되 한 화면의 입력은 하나의 큐로 관리한다. 이미 확보한 전체 대화를 매번 복사하는 대신 새 사실과 근거 위치만 공유한다.

## 7. 수집 종료와 제출을 분리한다
14:50에 수집을 마치고 마지막 근거를 반영한 뒤 테스트·디브리프·제출을 마쳤다. 제출 후에는 실행 시스템을 변경하지 않고 별도 폴더에 회고와 재사용 스킬을 만들었다.

## 가장 큰 교훈
‘최고의 질문 하나’보다 유용했던 것은 **실패가 드러난 업무에 대해 빠진 근거를 찾아 실행 결과로 다시 확인하는 반복**이었다. 발굴률은 신호지만 실전 정확도의 대체 지표는 아니다.
