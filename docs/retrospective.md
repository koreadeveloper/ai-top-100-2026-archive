## 잘했던 선택
흩어진 기록을 단순 요약에 그치지 않고 시점·범위·권한으로 대조했다. 공개 예시와 실제 도구 호출로 문제를 발견했고, 추측 ID 같은 제약은 코드로 옮겼다. 정책상 불가를 말한 뒤 가능한 대안을 제시하도록 보완했다. 오류와 실제 미확인 범위를 기록하고 제출 후에는 서비스를 동결했다.

## 아쉬웠던 선택
### 막힌 질문을 너무 오래 반복했다
동료 연락처를 제공하지 않는다는 답을 여러 번 받았다. 새로운 이름이 나왔다고 새로운 인터뷰 창구라고 생각하면 안 됐다. 조직과 도달 경로를 초반에 봤어야 했다.

### 정보 수집·개발·평가가 한 대화에 몰렸다
사용자는 카카오톡에 붙여넣고 답을 다시 복사해야 했다. 질문이 많아질수록 전송과 맥락 복구 비용이 컸다. 공통 원장과 역할별 결과 파일이 필요했다.

### 늦게 시작한 화면 자동화가 오히려 시간을 썼다
여러 질문을 만들 수 있어도 화면 전환과 대기는 줄지 않았다. 자동화는 한 건의 완료 시간으로 수동과 비교해야 한다. 사용자가 중단한 뒤에는 수동 작업을 유지했다.

### 점수와 지식발굴률에 시선이 쏠렸다
새로운 질문이 이미 확보한 원문 참조로 끝나는 일이 있었다. 실제로 고칠 실패와 아직 없는 근거를 먼저 정했어야 했다. 자체 평가 점수도 자동 판정의 사각지대가 있었다.

### 최종 버전 전체 평가 시간을 충분히 남기지 못했다
약점별 재평가는 했지만 최종 커밋의 전체15개 재평가를 끝내지 못했다. 다음에는 수집과 변경 종료 시간을 더 일찍 배정해야 한다.

## 다음에 유지할 원칙
- 최소 채널 연결을 먼저 만든다.
- 관찰·기억·원문·정책·권한·이행을 분리한다.
- 출처가 있는 ID와 본인 귀속을 각각 검증한다.
- 병렬화는 실제 독립 작업과 입력 병목을 기준으로 한다.
- 최종 버전·배포 버전·평가 버전을 맞춘다.
- 잘된 결과뿐 아니라 실패·미확인·시간 낭비도 남긴다.

이 아카이브는 완벽한 해법보다 다음 실행의 출발점을 남기는 기록이다.
